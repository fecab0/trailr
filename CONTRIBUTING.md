# Contributing to Trailr

Thanks for helping make Trailr better. Bugs, ideas, docs fixes and new skill references are all welcome.

## Before you start

- **Bugs and ideas:** [open an issue](https://github.com/fecab0/trailr/issues/new/choose) using one of the templates.
- **Small fixes** (typos, docs, an obvious bug): send a pull request directly.
- **Bigger changes** (a new step, a new script, a change to how the skill behaves): open an issue first so we can agree on the approach before you spend time on it.
- **Security problems:** do not open a public issue. See [SECURITY.md](SECURITY.md).

## Sending a pull request

1. Fork the repo and create a branch from `main`.
2. Keep the change focused: one topic per pull request.
3. If you touch `scripts/`, run the environment check and the pipeline by hand (see "Try the pipeline by hand" in the README) and say in the PR what you tested.
4. If you change how the skill behaves, update `SKILL.md` or the relevant file in `references/`.
5. Open the pull request and fill in the template.

Every pull request is reviewed by a maintainer. Nothing is merged without a maintainer's approval.

## Ground rules

- Never commit secrets, API keys, tokens, `.env` files or personal data, and never include real customer names or private URLs in examples.
- Only add media, fonts or footage you have the right to share, and note the license.
- Be kind. Disagree with ideas, not people.
